# Network Traffic Protocol Classification with a 1-D CNN

CSEC 520/620 project repository, laid out per the course
[project template](https://github.com/byuan/csec-520-620-project-template) so that
a grader can recreate the results in **one command**.

A 1-D convolutional neural network classifies TCP flows into 24 application
protocols (HTTP, SSL, SSH, LDAP, Kerberos, SMB, …) using only the first 1024
payload bytes of each flow. Data were captured at the 2017 national CPTC at RIT
and labelled with nDPI. The original study compared five optimizers (SGD, Adam,
RMSprop, SGD-Momentum, SGD-Nesterov); the optimizer is a single knob in
`config.yaml`.

Requires Python 3.10+ and `make`.

## Quick start

```bash
make setup            # python3 -m venv .venv && pip install -r requirements.txt
cp /path/to/dataset.csv data/cptc2017_flows.csv     # see data/README.md
make reproduce        # == .venv/bin/python -m src.train --config config.yaml
```

`make reproduce` trains the CNN (200 epochs, ~10 min on a laptop CPU, faster on a GPU) and writes to `results/`:

| file | contents |
|---|---|
| `metrics.json` | accuracy, macro precision / recall / F1, macro one-vs-rest ROC-AUC, per-class scores |
| `classification_report.txt` | scikit-learn per-class report |
| `confusion_matrix.png` | 24 × 24 confusion matrix on the 30 % test split |
| `roc_curve.png` | one-vs-rest ROC per class + macro average |
| `per_class_metrics.png` | precision / recall / F1 bar chart per protocol |
| `training_curves.png`, `history.json` | loss & accuracy vs. epoch (train / validation) |
| `model.pt` | best-validation-loss checkpoint (`state_dict`) |

Other targets: `make test` (smoke tests on synthetic data), `make lint`, `make clean`.
`bash scripts/seed_sweep.sh` retrains with seeds 1–3 and writes `results/seed_summary.json`
(mean ± std of every headline metric) — a variance estimate to quote alongside the single-seed
numbers above.

To run another optimizer, edit `train.optimizer` in `config.yaml`
(`SGD`, `Adam`, `RMSprop`, `SGD-Momentum`, `SGD-Nesterov`) and rerun `make reproduce`.

## Framework note

The model is written in **PyTorch** (`src/model.py` is an `nn.Module`, `src/train.py` is an
explicit training loop), matching the course template. The original study used Keras/TensorFlow;
the architecture, optimizers and checkpoint-on-best-validation-loss behaviour are the same.
`train.py` prints the device it runs on (`cuda: <GPU name>` or `cpu`) at startup; the PyPI
Linux `torch` wheel already includes CUDA, so no extra install is needed for an NVIDIA GPU.

## Differences from the original script

- Split is **stratified** by protocol (the original used a plain random split).
- Byte values are rescaled by a constant 1/255 (the original fed raw 0–255 values).
- Metrics are macro-averaged over the 24 classes and include ROC-AUC, as the course requires.
- Weights use Keras-style initialisation (Glorot-uniform, zero bias) so results stay comparable
  with the original TensorFlow implementation.
- Everything is seeded (`seed: 42`); results are identical run-to-run on the same CPU/backend
  but may differ slightly between CPU and GPU (cuDNN) builds.
